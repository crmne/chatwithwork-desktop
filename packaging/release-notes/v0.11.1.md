Chat with Work Desktop can now get a computer ready for a coding bot in one step: `cww coding setup` lends it a folder, signs in Claude Code with your own subscription, mirrors the repository and proves it all works in the sandbox. Sharing big folders of code no longer uses up the computer's file watches.

## New

- **Lend a computer to a coding bot in one step.** `cww coding setup --bot <number>` shares a folder with the bot, installs Claude Code if it's missing and signs it in with your own `claude setup-token`, mirrors and checks out the repository, installs its toolchain from a private copy, and runs its tests and Claude Code once in the sandbox, as the bot, saying how each step went. The token stays in the system's secret store (Keychain, Credential Manager, Secret Service) and reaches only that bot's commands in that folder, its text taken out of everything they print. The repository's mirror lives where no command can write it and is fetched with your own credentials or a deploy key; the checkout fetches from it without keys and can't push. The bot's page in Chat with Work says what a computer still needs. See [docs/coding-computers.md](https://github.com/crmne/chatwithwork-desktop/blob/main/docs/coding-computers.md). By @crmne ([#137](https://github.com/crmne/chatwithwork-desktop/pull/137)).
- **Fedora and openSUSE repositories.** Fedora installs and updates from COPR, and openSUSE from the Open Build Service, with `dnf` and `zypper`. The release's `.rpm` is Fedora's: openSUSE couldn't install it. By @crmne ([#139](https://github.com/crmne/chatwithwork-desktop/pull/139)).

## Fixed


- **Sharing a folder of code no longer starves the rest of the computer.** The search index watched every folder inside a shared one, `.git`, `node_modules`, build output and the folders that links led to included, and on Linux that could take almost every file watch the system allows (over 500,000 in one report). Other programs then couldn't watch files, and the desktop session could end. It now watches only the folders it indexes, at most 8,192 of them on Linux (or a tenth of the system's limit when that is less), and folders past that are brought up to date when a search asks and by the periodic rescan. By @crmne ([#143](https://github.com/crmne/chatwithwork-desktop/pull/143)).
- **Search leaves out dependencies and build output.** `node_modules`, Python virtual environments, build output inside a software project (`target`, `build`, `dist`, `vendor`, `tmp` and the like), marked caches and linked Git worktrees are no longer indexed, even where no `.gitignore` says so, and a folder called `build` or `vendor` in your documents still is. The `grep` and `glob` tools still search them. By @crmne ([#143](https://github.com/crmne/chatwithwork-desktop/pull/143)).
- **Fewer rescans on Mac and Windows.** Changes inside folders the index skips no longer set off a rescan. By @crmne ([#143](https://github.com/crmne/chatwithwork-desktop/pull/143)).

- **Commands get an empty standard input.** A program that waited for input (Claude Code waits three seconds) now sees its end at once. By @crmne ([#137](https://github.com/crmne/chatwithwork-desktop/pull/137)).
- **`cww` piped into `head` ends quietly.** It used to panic, and that reached crash reports, when its reader closed early. By @crmne ([#144](https://github.com/crmne/chatwithwork-desktop/pull/144), reported in [#136](https://github.com/crmne/chatwithwork-desktop/issues/136)).

## Known limitations

- **Very large shared folders on Linux update their deepest folders less promptly.** Past the watch limit, a change there shows up in search after the next search (a minute later at most) or the periodic rescan, not at once.
- **Some rule changes take effect within six hours, not at once.** Desktop can't watch Git's `.git/info/exclude`, or a `CACHEDIR.TAG` or `pyvenv.cfg` going away in a folder search skips, so it rebuilds its watches and rescans every six hours to catch them.
- **A token given to a bot's commands can be used by them.** Desktop takes its text out of what they print, which doesn't stop a command written to hide it, and, with the network, to send it elsewhere. Approve that bot's commands with that in mind, or revoke the token at claude.ai.
- **The real Claude Code hasn't been tried in a Windows sandbox yet.** It ran on Linux and macOS; on Windows the sign-in reaching only the allowed bot was tested with a stand-in.
- **Printing hasn't been tried on a physical printer.**
- **Linux animations can still remain at 60 fps.**
- **The browser extension is still installed manually.**
- **Linux updates use the package manager or one-line installer.** On Mac, use the signed and notarized DMG; the PKG remains unsigned. Windows SmartScreen may warn while the installer builds reputation.
