Chat with Work Desktop now keeps itself up to date: a new version installs the next time the app starts, never while a command runs, and a banner in the window says when one is waiting. Installs a package manager updates are told the exact command, with a Copy button, and there's now an AppImage and a Flatpak bundle for any Linux.

Already installed? On Mac and Windows, use **Restart to Update**; from this version on, updates install themselves. Otherwise upgrade through the package manager you used (`brew upgrade`, `apt`, `dnf`, `zypper`, `pacman`). ## New

- **Updates install themselves.** A new version on the same major version downloads in the background, signed and verified as before, and installs the next time Chat with Work starts, before any window opens. It waits while the background agent is running a command, and the agent moves to the new version only once no command runs. A version you went back from isn't installed again on your behalf. A new major version still asks first. **Install updates automatically** in General turns this off; it's on by default. On the Mac and Windows, and on the AppImage from the next release. The rules are shared with Solco through fastframe 0.16.1. By @crmne ([#149](https://github.com/crmne/chatwithwork-desktop/pull/149)).
- **A banner says when a new version is waiting.** At the top right of the window: **Restart to Update** once one is downloaded, or, for an install a package manager updates, the command that updates it the way you installed it (`yay -Syu chatwithwork-desktop-bin`, `sudo dnf upgrade --refresh chatwithwork-desktop`, `brew upgrade cww`, `nix profile upgrade …`), with a Copy button and the file to download when there's one. Desktop never runs the command. General and the tray say the same, and dismissing it hides it until the next version. It only shows a release whose signed `checksums.txt` checks out. By @crmne ([#149](https://github.com/crmne/chatwithwork-desktop/pull/149)).
- **An AppImage and a Flatpak bundle for any Linux.** Built from the same files as the `.deb` and `.rpm`, for x86_64 and Arm. The AppImage shows the update banner with AppImageUpdate's command; from the next release on, its release signs it too, and it updates itself like the Mac and Windows apps. By @crmne ([#147](https://github.com/crmne/chatwithwork-desktop/pull/147), [#149](https://github.com/crmne/chatwithwork-desktop/pull/149)).

## Known limitations

- **Updates install at the next start, not at quit.** Installing at the next start keeps the check that the new version opens, and the rollback if it doesn't. A Chat with Work that stays open for days installs at its next start, or with **Restart to Update**.
- **Copies from 0.11.1 and earlier need one Restart to Update.** They don't install updates by themselves yet; 0.12.0 and later do.
- **The AppImage and Flatpak bundle can't start the background agent at login yet.** In the Flatpak, run the agent yourself with `flatpak run --command=cww com.chatwithwork.desktop daemon run` ([#138](https://github.com/crmne/chatwithwork-desktop/issues/138)).
- **This release's AppImages aren't in its signed `checksums.txt`.** The step that adds them failed, so 0.12.0's AppImage tells you about the next version rather than installing it. The next release signs its AppImages.
- **The Flatpak bundle doesn't update itself.** No Flatpak repository publishes it yet, so Desktop shows the command that installs the new bundle.
- **Printing hasn't been tried on a physical printer.**
- **Linux animations can still remain at 60 fps.**
- **The browser extension is still installed manually.**
- **On Mac, use the signed and notarized DMG; the PKG remains unsigned.** Windows SmartScreen may warn while the installer builds reputation.
