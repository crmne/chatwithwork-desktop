A bot you lent a folder to can now ask to run its commands there without asking each time, and only this computer can say yes. A shared folder's commands can get their own environment variables, secrets included, kept in this computer's secret store and taken out of everything they print.

## New

- **A bot can ask to run its commands unattended.** When a bot you lent a folder to needs commands there without asking each time, it asks. Chat with Work Desktop shows **Allow** or **Not now** in its own dialog, naming the bot and the folder as this computer knows them. Without the app open, a notification says to open it, and `cww roots requests`, `cww roots allow` and `cww roots decline` answer it from a terminal. A request lasts a day. Neither the server nor a web page can say yes for you, and allowing does what sharing the folder with unattended commands already did: they still run in the folder's sandbox and are recorded. By @crmne ([#153](https://github.com/crmne/chatwithwork-desktop/pull/153)).
- **A folder's commands can have their own environment.** `cww roots env <folder> --stdin` keeps `NAME=value` lines, dotenv-style, in this computer's secret store (Keychain, Credential Manager, Secret Service), never in `config.toml`. Every command in the folder gets them. A value can be `$(command)`, which runs in the run's own sandbox when it starts, so a 1Password service account's token on one line lets `op read` fill the next. Values are taken out of everything a run prints, as `[redacted]`, and nothing about the list reaches Chat with Work, not even the names. See [docs/secrets.md](https://github.com/crmne/chatwithwork-desktop/blob/main/docs/secrets.md). By @crmne ([#154](https://github.com/crmne/chatwithwork-desktop/pull/154)).

## Fixed

- **The `zip` library is up to date with a security fix.** Desktop reads Word, Excel and PowerPoint files with the `zip` crate, now 9.2.3, which fixes [GHSA-m665-v7pm-7grj](https://github.com/advisories/GHSA-m665-v7pm-7grj), where an archive's two headers could name different files. By @crmne ([#155](https://github.com/crmne/chatwithwork-desktop/pull/155)); thanks Renovate for flagging it ([#135](https://github.com/crmne/chatwithwork-desktop/pull/135)).
- **The AppImage updates itself.** This release's AppImages are in its signed `checksums.txt`, so a 0.12.0 AppImage you own installs this version by itself. By @crmne ([#151](https://github.com/crmne/chatwithwork-desktop/pull/151)).

## Known limitations

- **Folder environments are set from a terminal.** The app doesn't have a field for them yet.
- **The AppImage and Flatpak bundle can't start the background agent at login yet.** In the Flatpak, run the agent yourself with `flatpak run --command=cww com.chatwithwork.desktop daemon run` ([#138](https://github.com/crmne/chatwithwork-desktop/issues/138)).
- **The Flatpak bundle doesn't update itself.** No Flatpak repository publishes it yet, so Desktop shows the command that installs the new bundle.
- **Printing hasn't been tried on a physical printer.**
- **Linux animations can still remain at 60 fps.**
- **The browser extension is still installed manually.**
- **On Mac, use the signed and notarized DMG; the PKG remains unsigned.** Windows SmartScreen may warn while the installer builds reputation.
