Commands on a Linux computer can now build software that compiles C: a Rust crate with a native dependency, a Ruby gem with an extension. They find the system's C headers in the sandbox. AppImages are in the signed `checksums.txt` again, so they update themselves.

## Fixed

- **Commands on Linux find the system's C headers.** The sandbox let a command read the computer's compilers and libraries but not `/usr/include`, so a compiler stopped at `stdio.h` and every build with native code failed: a Rust crate with a `-sys` dependency (ALSA, PulseAudio, SQLCipher), a gem with a C extension. Commands now read `/usr/include`, and can't change it. On a Mac, compilers already read their headers from the SDK. By @crmne ([#158](https://github.com/crmne/chatwithwork-desktop/pull/158)).
- **The AppImage updates itself.** 0.12.0's and 0.13.0's releases stopped before adding their AppImages to the signed `checksums.txt`, so an AppImage couldn't install 0.13.0 by itself, although 0.13.0's notes said it could. This release's AppImages are in it. By @crmne ([#159](https://github.com/crmne/chatwithwork-desktop/pull/159)).

## Known limitations

- **Folder environments are set from a terminal.** The app doesn't have a field for them yet.
- **The AppImage and Flatpak bundle can't start the background agent at login yet.** In the Flatpak, run the agent yourself with `flatpak run --command=cww com.chatwithwork.desktop daemon run` ([#138](https://github.com/crmne/chatwithwork-desktop/issues/138)).
- **The Flatpak bundle doesn't update itself.** No Flatpak repository publishes it yet, so Desktop shows the command that installs the new bundle.
- **Printing hasn't been tried on a physical printer.**
- **Linux animations can still remain at 60 fps.**
- **The browser extension is still installed manually.**
- **On Mac, use the signed and notarized DMG; the PKG remains unsigned.** Windows SmartScreen may warn while the installer builds reputation.
