Coding bots now run Claude Code with the sign-in this computer already has, and ask for your yes in a dialog: there's nothing to type and no token to paste. `grep` searches inside PDFs and Office documents, a computer runs as many commands at once as it has CPUs, and Desktop no longer puts secrets on a command line.

Chat with Work on a Mac now needs macOS 13.5 or later: macOS 11 and 12 are no longer supported. The browser engine runs on Node 26, which Node supports until April 2029.

## New

- **A coding bot asks, and you answer in the app.** When a bot that runs Claude Code first needs this computer, the app asks "Let Issue fixer run Claude Code in bots?" with Allow and Deny, naming the bot and folder as this computer knows them. Chat with Work can only ask; the answer is yours, here, or with `cww roots allow <root> <bot> --claude-code` on a server with no app. This needs a Chat with Work that asks, which goes live alongside this release. `cww coding setup` stays for scripts and servers, and picks the bot from a list by part of its name instead of asking for a number. By @crmne ([#162](https://github.com/crmne/chatwithwork-desktop/pull/162)).
- **`grep` searches documents.** PDF, Word (`.docx`), PowerPoint (`.pptx`) and spreadsheet files are searched in the text `read` returns for them, with the same line numbers, so an assistant can find a clause in a 200-page contract in a couple of calls instead of guessing where to read. The older `.doc` and `.ppt` aren't searched. By @crmne ([#164](https://github.com/crmne/chatwithwork-desktop/pull/164)).

## Changed

- **Coding runs use this computer's own Claude Code sign-in.** They read and write `~/.claude` and `~/.claude.json` (on Windows the `.claude` folder, and on a Mac they also reach the login keychain), so you sign in the normal way, once, and the token refreshes as it does for you. `cww coding sign-in` and `sign-out` are gone, and the first `cww coding` command deletes the token an earlier version kept. **What that yes gives a bot's commands:** they can read the tokens and your Claude Code history, and change Claude Code's settings, which the next `claude` you run yourself starts outside the sandbox. On a Mac they can also read other keychain items that let the `security` command read them. [docs/coding-computers.md](https://github.com/crmne/chatwithwork-desktop/blob/main/docs/coding-computers.md#claude-codes-sign-in) has the whole list. By @crmne ([#161](https://github.com/crmne/chatwithwork-desktop/pull/161)).
- **A yes from an earlier version doesn't carry over.** It covered one token, and this covers Claude Code's files, so a bot allowed Claude Code stops and asks again after you update. On a server with no app, run `cww coding allow <root> <bot>`, and sign in with `claude` first if you only ever used a token there. By @crmne ([#162](https://github.com/crmne/chatwithwork-desktop/pull/162)).
- **As many commands at once as the computer has CPUs, and no CPU time limit by default.** It was 4 commands and 600 CPU seconds per process, which a build on many cores spends in under a minute. The 30-minute limit on a run stays. A config with exactly the old numbers moves to the new ones, so to choose such a limit yourself, use another number. 0 means no limit on either. By @crmne ([#161](https://github.com/crmne/chatwithwork-desktop/pull/161)).
- **macOS 13.5 or later is required: macOS 11 and 12 are no longer supported.** Desktop carries its own copy of Node for the browser engine, and this release moves it from Node 22 to Node 26.12.1, which runs on macOS 13.5 or later only ([Node's supported platforms](https://github.com/nodejs/node/blob/v26.12.1/BUILDING.md#supported-platforms)). The app, the `.pkg`, the disk image and Homebrew now refuse older versions of macOS. On macOS 11 or 12, keep 0.13.1, the last version that runs there, or update macOS first. Windows and Linux need nothing new. By @crmne ([#105](https://github.com/crmne/chatwithwork-desktop/pull/105)).

## Fixed

- **Desktop puts no secret on a command line.** On Linux, Bubblewrap took a run's environment as its own arguments, so any user of the computer could read Claude Code's token and a folder's environment values with `ps`. Those values now reach a run through a private file it reads and deletes, and the token is gone. A command that passes a value to a program of its own can still show it the same way. If other people have accounts on a computer that ran coding bots, revoke that token at claude.ai (Settings, Claude Code), and change the values in its folder environments. By @crmne ([#161](https://github.com/crmne/chatwithwork-desktop/pull/161)).
- **Too many commands at once no longer reads as a rate limit.** `run` now answers `busy`, says how many are running, and says to wait for one to end. By @crmne ([#161](https://github.com/crmne/chatwithwork-desktop/pull/161)).
- **A spreadsheet can't take the computer's memory by being sparse.** An `.xlsx` is read one cell at a time, where two cells far apart in a tiny file used to ask for room for every cell between them. By @crmne ([#164](https://github.com/crmne/chatwithwork-desktop/pull/164)).
- **A covered click says what to do.** When something is drawn over an element, the browser tool says to scroll it into view or close the overlay, then read the page again and try again. By @crmne ([#166](https://github.com/crmne/chatwithwork-desktop/pull/166)).
- **Security updates of the `zip` library.** By Renovate ([#157](https://github.com/crmne/chatwithwork-desktop/pull/157), [#165](https://github.com/crmne/chatwithwork-desktop/pull/165), [#171](https://github.com/crmne/chatwithwork-desktop/pull/171)).

## Known limitations

- **Claude Code's own sign-in has been proved on Linux only.** The real Claude Code hasn't yet answered from the sandbox on a Mac's desktop session or on Windows, though the sandbox's rules are tested on each.
- **`.xls`, `.xlsb` and `.ods` files are still read whole,** so a crafted one can still use a lot of memory, as it could before.
- **A Mac on macOS 11 or 12 may still be offered this update.** The updater checks that a new version starts before it switches to it, so the app stays on 0.13.1, but it can keep offering the update.
- **Folder environments are set from a terminal.** The app doesn't have a field for them yet.
- **The AppImage and Flatpak bundle can't start the background agent at login yet.** In the Flatpak, run the agent yourself with `flatpak run --command=cww com.chatwithwork.desktop daemon run` ([#138](https://github.com/crmne/chatwithwork-desktop/issues/138)).
- **The Flatpak bundle doesn't update itself.** No Flatpak repository publishes it yet, so Desktop shows the command that installs the new bundle.
- **Printing hasn't been tried on a physical printer.**
- **Linux animations can still remain at 60 fps.**
- **The browser extension is still installed manually.**
- **On Mac, use the signed and notarized DMG; the PKG remains unsigned.** Windows SmartScreen may warn while the installer builds reputation.
