## New

- **Updates no longer wait for a new major version.** With **Install updates automatically** on, a downloaded release installs the next time the app starts, whatever its version number: Chat with Work Desktop goes with a website, not with anything you paid for by version. With the switch off, it still waits for **Restart to Update**. Nothing installs by itself while a command runs. If you went back to an older version, the app won't install anything up to the version you left, only something newer than that. By @crmne ([#172](https://github.com/crmne/chatwithwork-desktop/pull/172)).

## Fixed

- **A disconnected computer asks to connect.** At launch, and whenever the connection is lost for good, the app asks in its own dialog and leads straight to approving the computer in your browser. Retrying through a network blip stays quiet. The menu's first line is now the thing to press (Connect to Chat with Work…, or Reconnect…), never a greyed-out "Not connected". The same on Mac, Windows and Linux. By @crmne ([#172](https://github.com/crmne/chatwithwork-desktop/pull/172)).
- **A computer whose sign-in is gone is told to sign in again.** If the system's keychain lost the computer's key, the app kept treating it as paired. Settings said "Reconnecting to this computer" for ever, and nothing could connect it. Now it asks you to reconnect. By @crmne ([#172](https://github.com/crmne/chatwithwork-desktop/pull/172)).
- **A locked keychain no longer stops the connection until a restart.** The agent tries again by itself, from every five seconds up to every five minutes. By @crmne ([#172](https://github.com/crmne/chatwithwork-desktop/pull/172)).

## Known limitations

- **Claude Code's own sign-in has been proved on Linux only.** The real Claude Code hasn't yet answered from the sandbox on a Mac's desktop session or on Windows, though the sandbox's rules are tested on each.
- **`.xls`, `.xlsb` and `.ods` files are still read whole,** so a crafted one can still use a lot of memory, as it could before.
- **Folder environments are set from a terminal.** The app doesn't have a field for them yet.
- **The AppImage can't run the background agent as a service, and the Flatpak bundle can't start it at login or run commands.** For those, use a package or the terminal archive. In the Flatpak, run the agent yourself with `flatpak run --command=cww com.chatwithwork.desktop daemon run` ([#138](https://github.com/crmne/chatwithwork-desktop/issues/138)).
- **The Flatpak bundle doesn't update itself.** No Flatpak repository publishes it yet, so Desktop shows the command that installs the new bundle.
- **Printing hasn't been tried on a physical printer.**
- **Linux animations can still remain at 60 fps.**
- **The browser extension is still installed manually.**
- **On Mac, use the signed and notarized DMG; the PKG remains unsigned.** Windows SmartScreen may warn while the installer builds reputation.
