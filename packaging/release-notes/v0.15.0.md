## New

- **A coding bot gets this computer from one yes.** When a bot that codes needs this computer, Chat with Work shows a card with **Set up**, which opens the bot's page in the app. The app then asks in a window of its own, one no web page can see or answer: it shows what it checked (the agent is installed and signed in, your Git login reaches the repository, and the folder it will use, such as a new `~/bots`), says in one line what the bot's commands get, and offers **Allow** only while every check holds. Allow lends that folder to the bot with commands and the network, with this computer's own sign-in for that agent, for that repository's owner. Nothing to type, and `cww coding setup` stays for scripts and servers. By @crmne ([#179](https://github.com/crmne/chatwithwork-desktop/pull/179)).
- **The first run on a repository prepares it by itself.** It copies the repository with your own Git login (from an address your login reaches, never one the server gives), checks it out, installs its toolchain and dependencies, and runs its tests once, all in the sandbox and with no agent's sign-in. Each step shows live in the chat, and a step that fails is named on a card with Try again (and, for the tests, Go on without them). Only repositories of an owner you allowed are prepared; another owner brings the card back. What must outlast a run, such as package caches, stays in the folder's `.cww-tools/`. By @crmne ([#179](https://github.com/crmne/chatwithwork-desktop/pull/179)).
- **Codex, as well as Claude Code.** A bot's runs can use this computer's own Codex sign-in (`~/.codex`) with the same rules as Claude Code: only for the bot and folder you allowed, its tokens taken out of what a run prints. `cww coding setup --agent codex` and `cww coding allow <root> <bot> --agent codex` do it from a terminal. By @crmne ([#179](https://github.com/crmne/chatwithwork-desktop/pull/179)).

## Changed

- **Always allow on a bot's card works with one press.** When the computer's owner presses **Always allow** on a command's card (it names the computer), a folder already lent to that bot with commands on runs its commands without asking from then on, and the app shows a notice instead of asking again. It changes nothing else: it can't share or lend a folder, turn commands or the network on, or give a sign-in. It's recorded in the audit log, and you turn it off in Shared folders or with `cww roots share <folder> <bot>`. [docs/coding-computers.md](https://github.com/crmne/chatwithwork-desktop/blob/main/docs/coding-computers.md#letting-a-bots-commands-run-unattended-from-its-card) says what this widens. By @crmne ([#179](https://github.com/crmne/chatwithwork-desktop/pull/179)).

## Fixed

- **Claude Code on a Mac finds its sign-in in the keychain.** A run allowed Claude Code now has your login keychain where the `security` command looks for it; before, it searched only the system keychain. By @crmne ([#179](https://github.com/crmne/chatwithwork-desktop/pull/179)).

## Known limitations

- **Codex isn't available on macOS yet.** In the Mac's sandbox Codex stops at "Failed to synchronize managed preferences", and Desktop doesn't loosen the sandbox for it, so the Set up window says Codex can't run there.
- **Set up hasn't been tried on Windows.** On Linux, its checks and Allow were tried through the same control channel the window uses, against a development server with synthetic repositories.
- **The real Claude Code and Codex have run from the sandbox on Linux only.** On a Mac, the sandbox's rules and the first run are tested, but not a real agent's run.
- **On Windows, the first run can't install a repository's toolchain into the folder** when mise can't write its own install folder; that step's card says so.
- **A Codex that keeps its sign-in in the system keyring reads as not signed in.** Use Codex's file store (`cli_auth_credentials_store`).
- **`.xls`, `.xlsb` and `.ods` files are still read whole,** so a crafted one can still use a lot of memory, as it could before.
- **Folder environments are set from a terminal.** The app doesn't have a field for them yet.
- **The AppImage can't run the background agent as a service, and the Flatpak bundle can't start it at login or run commands.** For those, use a package or the terminal archive. In the Flatpak, run the agent yourself with `flatpak run --command=cww com.chatwithwork.desktop daemon run` ([#138](https://github.com/crmne/chatwithwork-desktop/issues/138)).
- **The Flatpak bundle doesn't update itself.** No Flatpak repository publishes it yet, so Desktop shows the command that installs the new bundle.
- **Printing hasn't been tried on a physical printer.**
- **Linux animations can still remain at 60 fps.**
- **The browser extension is still installed manually.**
- **On Mac, use the signed and notarized DMG; the PKG remains unsigned.** Windows SmartScreen may warn while the installer builds reputation.
