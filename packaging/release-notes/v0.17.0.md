Chat with Work can now press the unlabelled "×" and "X" controls pages draw, and says plainly when a banner covers the button it was asked to press. Folders indexed before show as ready at once after a restart, a pause that arrives while a command gets ready now stops it, and **Get extension** opens the Chrome Web Store.

## New

- **Unlabelled controls can be pressed.** A "×" that removes a row or an "X" that closes a banner, drawn with no role or name, now reads as clickable, named by its text or the text beside it. Since a glyph doesn't say what it does, pressing one asks first, with a screenshot of what will be pressed. Needs browser extension 0.1.4. By @crmne ([#225](https://github.com/crmne/chatwithwork-desktop/issues/225), [#227](https://github.com/crmne/chatwithwork-desktop/pull/227)).
- **Get extension opens the Chrome Web Store.** The Browser page's button leads to the extension's store listing, which also keeps it up to date, instead of its folder on GitHub. By @crmne ([#223](https://github.com/crmne/chatwithwork-desktop/pull/223)).

## Fixed

- **A button under a fixed banner gets a clear answer.** The button is scrolled clear of fixed and sticky layers first. If something still covers it, the click fails at once, says that nothing was clicked and names what covers it and where, such as a fixed banner along the bottom of the window, instead of answering that the result was uncertain. Needs browser extension 0.1.4. By @crmne ([#226](https://github.com/crmne/chatwithwork-desktop/issues/226), [#227](https://github.com/crmne/chatwithwork-desktop/pull/227)).

![A form whose Save button is under a cookie banner: the click fails at once with "Nothing was clicked" and names the fixed banner along the bottom of the window; from a synthetic test page](https://github.com/crmne/chatwithwork-desktop/releases/download/v0.17.0/covered-click.png)

- **Replacing text in a rich-text editor no longer copies its formatting.** Typing over a bold line made the new text bold. Desktop's bundled browser engine now deletes the old text first, as a person would, then types. A page that stops responding fails that step with a clear message, and later steps on its tab fail within seconds instead of waiting (with extension 0.1.4). By @crmne ([#218](https://github.com/crmne/chatwithwork-desktop/issues/218), [#227](https://github.com/crmne/chatwithwork-desktop/pull/227)).
- **Folders indexed before show as ready after a restart.** Allowing changes in a folder restarts the background agent, and every folder showed "Indexing…" from zero meanwhile. Now a folder that was indexed shows as ready at once and is checked again quietly. By @crmne ([#198](https://github.com/crmne/chatwithwork-desktop/issues/198), [#232](https://github.com/crmne/chatwithwork-desktop/pull/232)).

- **A pause, stop or narrowed setting that arrives while a command gets ready now reaches it.** Before, a command that was waiting on the keychain could start under the old settings. By @crmne ([#170](https://github.com/crmne/chatwithwork-desktop/issues/170), [#232](https://github.com/crmne/chatwithwork-desktop/pull/232)).
- **A folder's changes are made in the order the background agent received them.** A slow "Run commands on" can no longer land after a later "Off" and leave commands on. ## Known limitations

- **Where Linux refuses network namespaces, commands run with no network.** Ubuntu 23.10 and later refuse them with AppArmor, though Bubblewrap itself still runs. There, local services give nothing and nothing refused is reported, and a folder with the internet fails at once and says why.
- **Windows and Landlock give no local services.** A Windows process container can't reach this computer's loopback without an administrator's exemption for every app, and Landlock can't tell one address from another. On Windows a folder has None or the internet; on Landlock it has no network at all, and a folder with the internet fails at once and says why.
- **On Landlock, a program a command builds can't run.** `cc hello.c -o hello && ./hello` stops at "Permission denied", as it did in 0.15.0.
- **Only Linux with Bubblewrap says which connection was refused.** On macOS a refused connection fails at once too, but which one isn't said; Windows and Landlock don't say either.
- **On macOS, local services are loopback ports, and only the internet reaches another machine.** Exact local-network addresses can't be given there, a command still can't serve itself, and a service started after a command is reached only by running the command again.
- **On Linux, the memory limit needs the systemd service.** Where the agent runs another way (`cww daemon run` from a terminal, the AppImage, a container), commands have no memory limit. A service installed with `cww daemon install` before 0.16.0 gets one after `cww daemon install` again.
- **Narrowing a folder's network stops the commands running there,** since their sandboxes were made with the wider one.
- **Codex and OpenCode aren't available on macOS yet.** In the Mac's sandbox Codex stops at "Failed to synchronize managed preferences", and OpenCode's private server can't listen on a local port. Desktop doesn't loosen the sandbox for them, so the Set up window says they can't run there.
- **A Codex that keeps its sign-in in the system keyring reads as not signed in.** Use Codex's file store (`cli_auth_credentials_store`).
- **`.xls`, `.xlsb` and `.ods` files are still read whole,** so a crafted one can still use a lot of memory, as it could before.
- **Folder environments are set from a terminal.** The app doesn't have a field for them yet.
- **The AppImage can't run the background agent as a service, and the Flatpak bundle can't start it at login or run commands.** For those, use a package or the terminal archive. In the Flatpak, run the agent yourself with `flatpak run --command=cww com.chatwithwork.desktop daemon run` ([#138](https://github.com/crmne/chatwithwork-desktop/issues/138)).
- **The Flatpak bundle doesn't update itself.** No Flatpak repository publishes it yet, so Desktop shows the command that installs the new bundle.
- **Printing hasn't been tried on a physical printer.**
- **Linux animations can still remain at 60 fps.**
- **On Mac, use the signed and notarized DMG; the PKG remains unsigned.** Windows SmartScreen may warn while the installer builds reputation.
- **Allowing changes in a folder still restarts the background agent.** Folders indexed before now show as ready at once and are checked again quietly.

- **The browser fixes need extension 0.1.4,** apart from rich-text typing, which Desktop's bundled engine does. The Chrome Web Store has offered 0.1.4 since its review passed; the [manual ZIP](https://github.com/crmne/chatwithwork-desktop/releases/tag/browser-v0.1.4) has it too.
- **Another extension's popup over a field can leave a tab unreadable** ([#237](https://github.com/crmne/chatwithwork-desktop/issues/237)).
- **`cww roots` changes don't go through the daemon's ordered edit yet,** so a stalled change from the app can still undo one made in a terminal ([#239](https://github.com/crmne/chatwithwork-desktop/issues/239)).
- **On Windows, a pause pressed while a thinking step gets ready can miss it** ([#240](https://github.com/crmne/chatwithwork-desktop/issues/240)).
- **A folder that was missing when Desktop started stays "Folder not found" after it appears** until the background agent restarts ([#241](https://github.com/crmne/chatwithwork-desktop/issues/241)).
