Chat with Work can now upload files from a folder you share to a site in your browser, and save one of a chat's files on this computer, so a file made in a chat or kept on your other computer reaches a site in two steps. On pages drawn without buttons it can name, such as a canvas, it clicks, drags and presses keys on a screenshot, showing you the spot first. Files of up to 200 MB now go into a chat as well as out of one, and the terminal app draws in your terminal's own colours.

## New

- **Upload files from a folder you share to a site.** Chat with Work can hand files to a page's upload field, to a button that opens a file picker, or drop them on a drop zone, up to 10 files of up to 200 MB each in your browser's "Chat with Work" tab group. Every upload asks you, every time and in every permission mode, with each file's name, size, kind and folder, the site and the field. The browser gets a private copy of exactly the file you approved, so a file changed after you said yes isn't sent. Password, card and one-time code fields are never filled in. By @crmne ([#245](https://github.com/crmne/chatwithwork-desktop/pull/245)).
- **Save one of a chat's files on this computer.** A file made in a chat, attached to it, or copied into it from your other computer can be saved here as a new file, up to 200 MB, in a folder that allows changes, on a card of its own. It never replaces a file, and it's kept only if it's exactly the file the card showed. Saving it, then uploading it, is how a chat's file reaches a site: two steps, two cards. By @crmne ([#245](https://github.com/crmne/chatwithwork-desktop/pull/245)).
- **The extension says when uploads need a switch.** A browser hands files to pages only while the extension's **Allow access to file URLs** is on. The extension's menu and this app's Browser page say so, with where to turn it on, and an upload asked for while it's off explains the same. By @crmne ([#245](https://github.com/crmne/chatwithwork-desktop/pull/245)).

![The save card: the chat's file, its size and kind, and the new file it will be in a shared folder; from a test with synthetic data](https://github.com/crmne/chatwithwork-desktop/releases/download/v0.18.0/save-card.png)

![A synthetic developer console after the upload, its field holding the 15 MB app bundle it received](https://github.com/crmne/chatwithwork-desktop/releases/download/v0.18.0/upload-result.png)

- **Click, drag and press keys on pages drawn without buttons.** A seat map on a canvas, a drawn calendar, a custom slider or a board you drag cards on gives no button to name, so Chat with Work now works from a screenshot of the tab: it clicks, double-clicks or drags at a spot, points to show a tooltip, and presses keys such as Tab, Enter, Escape and the arrows. The card shows the screenshot with the spot marked (a drag, both ends). Something the page draws itself counts as a click that may send something, so it asks. Every action is tied to the screenshot it points at, and if the page moved, scrolled or changed under that spot since, nothing happens and it looks again. By @crmne ([#248](https://github.com/crmne/chatwithwork-desktop/pull/248)).
- **Files of up to 200 MB go into a chat.** Copying a file from this computer into a chat now goes over HTTPS, as saving one does, instead of through the agent's connection, so the limit goes from 25 MB to 200 MB. By @crmne ([#249](https://github.com/crmne/chatwithwork-desktop/pull/249)).

## Fixed

- **The terminal app uses your terminal's colours.** `cww tui` painted its own near-black background, so it sat as a dark block on a light or themed terminal. Now it keeps the terminal's background and palette, with bold, dim and reverse for hierarchy and the terminal's own colours only for state (done, working, waiting, failed), and `NO_COLOR` gets no colour at all. By @crmne ([#251](https://github.com/crmne/chatwithwork-desktop/pull/251)).

![The terminal app on a light terminal: no dark block, its text in the terminal's own colours; from synthetic data](https://github.com/crmne/chatwithwork-desktop/releases/download/v0.18.0/terminal-colours.png)

- **Dependency update.** `zip` 9.7.1. Renovate flagged it for [GHSA-m665-v7pm-7grj](https://github.com/zip-rs/zip2/security/advisories/GHSA-m665-v7pm-7grj), the advisory 0.17.0 already listed: Desktop has had the fix since before 0.13.0 ([docs/zip-review.md](https://github.com/crmne/chatwithwork-desktop/blob/main/docs/zip-review.md)), so it doesn't change what Desktop does. ## Known limitations

- **The browser features need extension 0.1.5.** The Chrome Web Store offers 0.1.4 until its review of 0.1.5 passes; the [manual ZIP](https://github.com/crmne/chatwithwork-desktop/releases/tag/browser-v0.1.5) has it now. An older extension asks you to update.
- **Uploads need Allow access to file URLs,** which only you can turn on, in `chrome://extensions`, Chat with Work's Details.
- **Sites that pick files with the File System Access API (`showOpenFilePicker`) can't be uploaded to.** No extension can answer that picker. Ordinary upload fields and drop zones work.
- **Fields and spots inside another site's frame are refused,** for uploads and for clicking by position, like embedded payment forms.
- **A file reaches a site only from this computer.** A chat's file, or one from your other computer, is saved here first, on its own card.
- **After Chat with Work restarts, a computer can now and then say it's connected while chats see it offline,** until its background agent restarts ([#246](https://github.com/crmne/chatwithwork-desktop/issues/246)).
- **Another extension's popup over a field can leave a tab unreadable** ([#237](https://github.com/crmne/chatwithwork-desktop/issues/237)).
- **`cww roots` changes don't go through the daemon's ordered edit yet,** so a stalled change from the app can still undo one made in a terminal ([#239](https://github.com/crmne/chatwithwork-desktop/issues/239)).
- **On Windows, a pause pressed while a thinking step gets ready can miss it** ([#240](https://github.com/crmne/chatwithwork-desktop/issues/240)).
- **A folder that was missing when Desktop started stays "Folder not found" after it appears** until the background agent restarts ([#241](https://github.com/crmne/chatwithwork-desktop/issues/241)).
