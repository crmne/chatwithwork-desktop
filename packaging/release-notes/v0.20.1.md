## New

- **Stopping sharing a folder a bot works in asks first, and names the bots.** "Stop sharing “chatwithwork”? Issue fixer (bot 34) and bot 62 use it, and stop working on this computer until it's shared with them again." Stop Sharing goes ahead; anything else keeps the folder. It asks in the app's own dialog, from Chat with Work's Settings in the app's window and from the app's own Shared folders alike. A bot lent the folder while the question was open keeps it: the background agent checks the bots again as it removes the folder. Other folders are still removed at once. By @crmne ([#277](https://github.com/crmne/chatwithwork-desktop/pull/277)).
- **The activity log says where a folder was stopped from:** the app, a Chat with Work page in its window, `cww`, or the terminal app (`via` on `root_removed`). By @crmne ([#277](https://github.com/crmne/chatwithwork-desktop/pull/277)).
- **`cww coding status` warns before Claude Code's sign-in ends.** A sign-in ends for good on a date Claude Code keeps, which renewing it doesn't move. Within two days of it, status says how many hours are left and to run `claude auth login` before then. By @crmne ([#276](https://github.com/crmne/chatwithwork-desktop/pull/276)).

## Fixed

- **A sign-in that has ended counts as not signed in,** so a bot's run hears it before it starts instead of printing "Run claude auth login now" and timing out 25 minutes later. Chat with Work then asks to sign Claude Code in again on that computer, with the command. By @crmne ([#276](https://github.com/crmne/chatwithwork-desktop/pull/276), [#278](https://github.com/crmne/chatwithwork-desktop/pull/278)).

![cww coding status saying Claude Code's sign-in has ended and Bot 42 isn't signed in; synthetic data](https://github.com/user-attachments/assets/6d1c1b01-fe35-4980-9184-cf4a180d3b8c)

- **A bot's computer no longer reads "ready" while Claude Code isn't signed in there.** Chat with Work asked the computer which folders a bot could code in, and the answer came from the settings file alone. It now says "not signed in" where the sign-in is missing or has ended. By @crmne ([#278](https://github.com/crmne/chatwithwork-desktop/pull/278)).
- **A repository prepared before is fetched before Desktop reads what it needs.** Nothing fetches a repository while no command runs in its folder, so after a quiet night it read the project's services from a copy hours old. `cww coding status` also says a copy's age in hours or days, and when it's fetched next. By @crmne ([#274](https://github.com/crmne/chatwithwork-desktop/pull/274)).
- **Dependency updates.** `url` 2.5.9 and `cookie` 0.18.3, for [RUSTSEC-2026-0592](https://rustsec.org/advisories/RUSTSEC-2026-0592) and [RUSTSEC-2026-0594](https://rustsec.org/advisories/RUSTSEC-2026-0594). By @crmne ([#275](https://github.com/crmne/chatwithwork-desktop/pull/275)).

## Known limitations

- **Chat with Work shows "Sign Claude Code in again" only once this version runs on that computer.** Older versions keep saying "ready", and their runs hear it from Claude Code itself.
- **After Chat with Work restarts, a computer can now and then say it's connected while chats see it offline,** until its background agent restarts ([#246](https://github.com/crmne/chatwithwork-desktop/issues/246)).
- **Another extension's popup over a field can leave a tab unreadable** ([#237](https://github.com/crmne/chatwithwork-desktop/issues/237)).
- **`cww roots` changes don't go through the daemon's ordered edit yet,** so a stalled change from the app can still undo one made in a terminal ([#239](https://github.com/crmne/chatwithwork-desktop/issues/239)).
- **On Windows, a pause pressed while a thinking step gets ready can miss it** ([#240](https://github.com/crmne/chatwithwork-desktop/issues/240)).
- **A folder that was missing when Desktop started stays "Folder not found" after it appears** until the background agent restarts ([#241](https://github.com/crmne/chatwithwork-desktop/issues/241)).
