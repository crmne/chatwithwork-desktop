Chat with Work Desktop is now Chat with Work itself, in a window of its own: the real web app from your server, so it's always current, beside the background agent's settings and its tray item. You can lend shared folders to Chat with Work bots, and Windows no longer needs the Visual C++ Redistributable.

**Download:** [macOS app](https://github.com/crmne/chatwithwork-desktop/releases/download/v0.4.0/chat-with-work-v0.4.0-macos-universal.dmg), [Windows installer](https://github.com/crmne/chatwithwork-desktop/releases/download/v0.4.0/cww-v0.4.0-x86_64-pc-windows-msvc.msi), [Debian/Ubuntu package](https://github.com/crmne/chatwithwork-desktop/releases/download/v0.4.0/chatwithwork-local-agent_0.4.0_amd64.deb), or [Fedora package](https://github.com/crmne/chatwithwork-desktop/releases/download/v0.4.0/chatwithwork-local-agent-0.4.0-1.x86_64.rpm). Arm builds and portable archives are in the release assets. On Arch, upgrade `chatwithwork-local-agent-bin`; on macOS, use `brew upgrade --cask chat-with-work`.

## New

- **Chat with Work in its own window.** Open Chat with Work from the tray or the applications menu and you get the web app itself, from the server this computer is paired with (chatwithwork.com, or your own), on a new chat in the organization you used last. Links that leave Chat with Work open in your browser, files you drop on the window go to the composer, downloads go to your Downloads folder, and dictation uses the microphone. It keeps you signed in, and remembers its size and place. By @crmne ([#17](https://github.com/crmne/chatwithwork-desktop/pull/17)).
- **Signing in with Google, Slack or Dropbox, and connecting services, happen in your browser.** Google doesn't allow either inside an app's web view, so the window hands them to your browser, which hands the result back. Nothing in your browser is signed in for you. By @crmne.
- **The settings are built into the app and work offline.** Welcome, shared folders, what's always private, activity, pairing, notifications and general settings are pages of the app, in Chat with Work's style, before pairing and without a network. Organizations, people and notification preferences are in Chat with Work's own settings, in the window. By @crmne ([#17](https://github.com/crmne/chatwithwork-desktop/pull/17)).
- **Lend folders to Chat with Work bots.** A bot reaches this computer only through the folders you lend it, from Shared Folders or `cww roots lend`, and where a folder allows commands, you decide here whether the bot's commands start without anyone approving each one. By @crmne ([#18](https://github.com/crmne/chatwithwork-desktop/pull/18)).
- **An offline page instead of an error.** When your server can't be reached, the window says so, retries on its own, and goes back where you were. By @crmne.
- **A new name: Chat with Work Desktop**, at [github.com/crmne/chatwithwork-desktop](https://github.com/crmne/chatwithwork-desktop). The `cww` command, the package names and your settings stay as they were, so this upgrades in place.

## Fixed

- **Windows starts without the Visual C++ Redistributable.** A fresh Windows 11 couldn't start `cww`, the agent or the app (error 0xC0000135), and the installer's agent setup failed silently. Everything now carries its own C runtime. By @crmne ([#15](https://github.com/crmne/chatwithwork-desktop/pull/15)).

## Known limitations

- **The app's native chat window is gone.** Chats are the web app now; the terminal interface, `cww tui`, keeps its own. The native app is kept at the [`egui-final`](https://github.com/crmne/chatwithwork-desktop/tree/egui-final) tag.
- **Linux needs WebKitGTK 4.1 and glibc 2.39 or newer:** Ubuntu 24.04+, Debian 13+, Fedora 40+. Rocky and RHEL 10 don't ship WebKitGTK 4.1, so the desktop package doesn't install there; the terminal-only `cww` archives still work. A tray that shows StatusNotifierItems keeps the app reachable when its windows close.
- **On macOS and Windows, a connection lost while a page is open shows the web view's own error** until you reopen the window; only Linux switches to the offline page then.
- **Windows builds and the macOS `.pkg` remain unsigned.** The macOS `.dmg` is signed and notarized. Windows may show a SmartScreen warning.
- **WinGet is coming.** The `ChatWithWork.Desktop` submission to WinGet follows this release; until it's accepted, use the MSI.
- **The app does not update itself.** Upgrade through your package manager or download this release. After upgrading a Linux package, run `systemctl --user restart cww.service`.
