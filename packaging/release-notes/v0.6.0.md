Chat with Work Desktop now keeps this computer's settings where the rest of your settings are: in Chat with Work's Settings, under This computer. Scans go into Chat with Work's own composer, where you write your message with everything the composer has, and notifications turn themselves on at first launch, on Windows too.

## New

- **This computer's settings are in Chat with Work's Settings.** Settings, This computer shows what this computer shares: pause sharing, rename a folder, stop sharing it, and turn changes, commands and their network on or off, beside the rest of your settings. Settings in the tray and Ctrl+, (Cmd+, on macOS) open it once the computer is paired. Anything that shares more (resuming, allowing changes, commands or the network) asks you first in a dialog the app draws itself, which no web page can see or answer, and a new folder comes only from the system's folder picker. The page never learns where a folder is on your computer. Activity, what's always private, lending folders to bots and the app's own preferences stay in the app's settings window, linked from the page. By @crmne ([#30](https://github.com/crmne/chatwithwork-desktop/pull/30)).
- **Scans go into Chat with Work's composer.** Scan a document… in the composer's + menu opens the scan window, and Attach to Message puts the PDF in that composer. From the tray, Continue in a New Chat opens a new chat with the scan attached, waiting for your message. Either way you write it in the composer, with dictation, more files, the model picker and web search, and nothing is sent until you press Send. Sending a scan to a bot and Save to Computer are in the finish button's menu. By @crmne ([#30](https://github.com/crmne/chatwithwork-desktop/pull/30)).
- **Notifications turn on at first launch.** The app asks for them once, the first time it starts: macOS shows its prompt, and Windows shows a first notification. Linux needs nothing turned on. By @crmne ([#27](https://github.com/crmne/chatwithwork-desktop/pull/27)).
- **A tidier tray menu.** A shorter headline ("Sharing 2 folders"), no empty line under it when there's nothing more to say, and Open, Scan…, Pause Sharing, then Settings and Quit. By @crmne ([#30](https://github.com/crmne/chatwithwork-desktop/pull/30)).
- **Fewer files to choose from.** Each release now has 17 files instead of 24, and these notes start with a table naming the one to download. The macOS app's `.zip` and the portable Windows `.zip` files are gone; use the `.dmg`, the MSI, Homebrew or WinGet. By @crmne ([#30](https://github.com/crmne/chatwithwork-desktop/pull/30)).

## Fixed

- **Turning on notifications works on Windows.** "Turn on native notifications…" did nothing there, since Windows has no permission prompt. It now shows a first notification, and Windows lists Chat with Work's notifications under its own name and icon. By @crmne ([#27](https://github.com/crmne/chatwithwork-desktop/pull/27)).
- **Updated Tokio for RUSTSEC-2026-0386.** By @crmne ([#28](https://github.com/crmne/chatwithwork-desktop/pull/28)).

## Known limitations

- **This computer in Settings and scanning into the composer need Chat with Work's matching update.** chatwithwork.com updates with this release; upgrade a self-hosted server to its next release before upgrading its computers.
- **Scanning needs a few things on Linux and macOS.** On Linux, SANE and Tesseract with your language. On macOS, SANE from Homebrew (`brew install sane-backends`). Windows needs only the scanner's TWAIN driver. macOS's own Image Capture and Windows' WIA scanners aren't supported yet.
- **Windows builds and the macOS `.pkg` remain unsigned.** The macOS `.dmg` is signed and notarized. Windows may show a SmartScreen warning.
- **On macOS and Windows, a connection lost while a page is open shows the web view's own error** until you reopen the window; only Linux switches to the offline page then.
- **On Windows on Arm, `cww tui` dictates only in the cloud.**
- **Linux needs WebKitGTK 4.1 and glibc 2.39 or newer** for the desktop package; the terminal-only `cww` archives still work elsewhere.
- **The app does not update itself.** Upgrade through your package manager or download this release. After upgrading a Linux package, run `systemctl --user restart cww.service`.
