Chat with Work Desktop's Windows installers are now signed by PlentyLabs, so Windows names who made them. Buttons that ask before acting, like Disconnect, work again in the Chat with Work window, and Chat with Work can now use your own browser through the new Chat with Work browser extension, only in its own tab group and on the sites you allow.

## New

- **Windows installers are signed by PlentyLabs.** The MSI installers, and the `cww`, `cww-agent`, Chat with Work and scanner programs inside them, carry a signature from PlentyLabs UG (haftungsbeschränkt) & Co. KG through Microsoft's Artifact Signing, with a timestamp, so Windows shows PlentyLabs as the publisher instead of an unknown one. Every signature is checked before the files are published. By @crmne ([#31](https://github.com/crmne/chatwithwork-desktop/pull/31)).
- **Chat with Work can use your own browser.** With the Chat with Work browser extension in Chrome, Edge, Brave, Vivaldi or Chromium, Chat with Work reads pages with your sign-ins, only in tabs in its own "Chat with Work" tab group and only on the sites you allow. It never reads what's typed in password, card or one-time code fields, and blurs them in screenshots. By @crmne ([#20](https://github.com/crmne/chatwithwork-desktop/pull/20)).
- **It can act on pages too, each action approved.** Turn on Allow actions and Chat with Work can open pages, click, type, choose and save files, each after you approve it in Chat with Work. Anything that may send, buy, post or delete shows you a screenshot of the page with the button outlined first, and a click that would submit a form without saying so is refused. By @crmne ([#21](https://github.com/crmne/chatwithwork-desktop/pull/21)).
- **Your Browser in the app's settings.** Turn the browser on, see which browser is connected, allow actions, add and remove sites, and lend the browser to bots, all on one page. Stop Using the Browser in the tray, Stop in the extension's menu, or pausing sharing stops it at once. By @crmne ([#23](https://github.com/crmne/chatwithwork-desktop/pull/23)).

## Fixed

- **Buttons that ask before acting work in the Chat with Work window.** Disconnect on a service, and every other button in Chat with Work that asks you to confirm, did nothing in the app's window. They now ask in the system's own dialog, titled with your Chat with Work server's address, and go ahead when you say yes. By @crmne ([#39](https://github.com/crmne/chatwithwork-desktop/pull/39)).
- **WinGet links to the right privacy policy.** By @crmne ([#29](https://github.com/crmne/chatwithwork-desktop/pull/29)).
- **Updated dependencies.** By Renovate ([#34](https://github.com/crmne/chatwithwork-desktop/pull/34), [#57](https://github.com/crmne/chatwithwork-desktop/pull/57) and others in the full changelog).

## Known limitations

- **The browser extension isn't in the Chrome Web Store yet.** Until it is, load it by hand: build it from [`browser/`](https://github.com/crmne/chatwithwork-desktop/tree/main/browser#trying-it) and add it at `chrome://extensions` with "Load unpacked". The browser has been tested on Linux with Chromium; macOS and Windows are untested so far.
- **Using the browser needs Chat with Work's matching update.** chatwithwork.com has it; a self-hosted server needs Chat with Work 0.15.0 or newer.
- **The macOS `.pkg` remains unsigned.** The macOS `.dmg` is signed and notarized, and the Windows installers are now signed.
- **Confirmations in the app's window have been tested on macOS and Linux (X11)**, not yet on Windows or on a Wayland desktop.
- **The app does not update itself.** Upgrade through your package manager or download this release. After upgrading a Linux package, run `systemctl --user restart cww.service`.

The other limitations in [0.6.0's notes](https://github.com/crmne/chatwithwork-desktop/releases/tag/v0.6.0) still apply.
