## Fixed

- **Commands work on Mac.** On a Mac, every command failed to start with "the sandbox can't hold this folder's rules", because Chat with Work Desktop asked macOS's sandbox for a memory limit it can't enforce. It no longer does, and the approval card lists only the limits that hold on a Mac: CPU time for each process and the time for the whole run. Tested on a Mac mini with approved runs, a failing one, the network off and on, the CPU limit, background runs followed and stopped in `cww tui` and from a chat, and the sandbox refusing to read or write outside its folder. By @crmne ([#76](https://github.com/crmne/chatwithwork-desktop/pull/76)).
- **Scans attached in the composer are PDFs again.** A scan attached to a message from the scan window reached Chat with Work as a larger text file named `.pdf`, which couldn't be previewed and which the models refused, so the question failed. It now arrives as the PDF. By @crmne ([cbcfebd](https://github.com/crmne/chatwithwork-desktop/commit/cbcfebd)).
- **Updated dependencies**, among them libloading, lopdf and quick-xml. By Renovate ([#64](https://github.com/crmne/chatwithwork-desktop/pull/64), [#66](https://github.com/crmne/chatwithwork-desktop/pull/66), [#67](https://github.com/crmne/chatwithwork-desktop/pull/67) and others in the full changelog).

## Known limitations

- **On a Mac, a command has no memory or process limit.** macOS's sandbox can't hold a memory limit, and nothing counts a command's processes there yet; CPU time for each process and the time for the whole run still stop it.
- **Commands don't run on Windows yet.** They're coming in a later release.
- **SmartScreen may still warn about a downloaded Windows installer** while the new signature builds its reputation. More info names PlentyLabs as the publisher, and Run anyway installs it. `winget install` and the PowerShell one-liner don't show this warning.
- **The app does not update itself.** Upgrade through your package manager or download this release. After upgrading a Linux package, run `systemctl --user restart cww.service`.

The other limitations in [0.6.2's notes](https://github.com/crmne/chatwithwork-desktop/releases/tag/v0.6.2) still apply.
