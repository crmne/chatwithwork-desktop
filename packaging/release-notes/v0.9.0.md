Your computer’s settings now live inside Chat with Work’s main Settings. Shared folders, browser access, notifications and app preferences stay in one window. Choose what each bot can use from that bot’s settings, edit custom file exclusions locally, and drive the browser extension from Codex or another local terminal agent through guarded browser commands. Private file paths, activity and exclusions stay on your computer.

## New

- **Local agents can use your browser extension.** `cww browser tools` lists the available browser operations and `cww browser call` runs them from the terminal, including Codex. The same allowed sites, Chat with Work tab group, protected-field checks, limits and audit still apply. Changes need an explicit approval flag after the caller obtains your authorization; it does not install a separate MCP server or expose arbitrary JavaScript. By @crmne.
- **Edit custom exclusions in Settings.** Add a file or folder pattern at the bottom of Shared folders. Editing or removing it asks on this computer because it can expose more files. Built-in protections stay read-only, and your patterns never enter the website’s page. By @crmne.

- **One window for your computer’s settings.** Settings has a **This computer** group: Shared folders, Browser, General, Notifications, Account, then Activity. App preferences open there, with native dialogs for folder picking and approvals. Before pairing or while offline, the local settings use that same window. By @crmne.
- **Folder access is easier to understand.** Each folder shows file changes, commands and network access together, plus the bots using it. Add folder sits at the end of the list, with **Excluded files and folders** below it. The page explains when commands also need your organization’s permission. By @crmne.
- **Choose a bot’s access where you configure the bot.** Open its existing computer integration to share folders or the browser. Sharing more still asks on this computer; stopping sharing takes effect immediately. The Settings page lists who uses a folder without mixing those grants into general preferences. The terminal commands now say `share` and `unshare`; older command names remain compatible. By @crmne.
- **Local information stays local.** The settings pane is bundled with the app, separate from the website’s page. File paths, activity, exclusions and grant details are not handed to the website. Menus and dialogs hide the pane without losing an unfinished folder rename, and keyboard navigation moves between the settings links and local controls. By @crmne.

## Fixed

- **Browser connections recover after Desktop restarts.** The extension announces itself again when its native host reconnects, including its Stop state. By @crmne ([2273f51](https://github.com/crmne/chatwithwork-desktop/commit/2273f51)).
- **Opening a browser tab works while an app or popup has focus.** A new tab joins the group in its own browser window, and a failed group setup leaves no stray target tab. By @crmne ([5b86cb1](https://github.com/crmne/chatwithwork-desktop/commit/5b86cb1)).
- **Bot sharing fits its controls.** The computer integration uses a compact disclosure instead of reserving most of a window. Closing it hides the native pane immediately. By @crmne.

## Known limitations

- **The integrated navigation and bot controls need a current Chat with Work server.** With an older self-hosted server, existing sharing keeps working and local preferences open in the same window. Until the server is updated, change bot grants with `cww roots share` or `cww roots unshare`, and `cww browser share` or `cww browser unshare`.
- **On Linux the app does not update itself.** Update through your package manager or run the one-line installer again. Versions before 0.7 also need one manual update on Mac and Windows.
- **SmartScreen may still warn about a downloaded Windows installer** while its signature builds a reputation. The PowerShell installer is another way to install it.
- **The browser extension is not in the Chrome Web Store yet.** Follow the [manual installation instructions](https://github.com/crmne/chatwithwork-desktop/tree/main/browser#trying-it) until its listing is approved.
- **On a Mac, commands have CPU and elapsed-time limits, but no memory or process-count limit.**
- **The Mac `.pkg` installer remains unsigned.** Use the signed and notarized `.dmg` for the app.
- **A previous Linux startup crash remains under observation.** The 0.6.2 report did not retain enough detail to prove that the display check covers every cause ([#77](https://github.com/crmne/chatwithwork-desktop/issues/77)).
