## Fixed

- **Coding sessions can keep going.** The default limits of 30 changes per minute and 500 per day are removed, along with the default tool-call and hourly write-volume quotas. Saved old defaults migrate automatically. Explicit custom quotas and file-size limits still apply. By @crmne.
- **Adding a large folder keeps settings responsive.** Index opening happens in the background, and changing folder access no longer waits for a complete scan before the worker restarts. Interrupted scans preserve existing index entries. By @crmne.
- **Updates keep the background processes together.** A new worker refuses an outdated supervisor, and opening the updated app reconciles a running older agent. This prevents the settings-parser errors that could stop every command after an upgrade. By @crmne.
- **Linux command sandboxes can start under the installed service.** The service supports their namespace setup and JIT runtimes. Linux packages include the helpers needed for network-enabled commands; folder isolation remains enforced by the daemon and each command's sandbox. By @crmne.
- **Ruby and Node installed through mise can run.** Their wrapper files and locks stay inside each command’s private home, while installed runtimes remain read-only. By @crmne.
- **Allow changes and Run commands ask once.** Turn on the switch and confirm inline. The duplicate system dialog is gone; the confirmation stays inside the app-owned settings pane and expires if its account or folder changes. By @crmne.
- **Computer settings fit the window.** Linux uses the actual web-page area for its native pane, keeping card edges and controls inside the window. Resizing a window cancels a confirmation if it would no longer fit. By @crmne.
- **Startup uses the right background.** The first window appears with its page loaded, with a bounded loading fallback for slow connections. Native settings also use the selected theme before their content paints. Exclusions span the same width as the folder cards. By @crmne.
- **Browser controls use the complete upstream engine.** Clicks, typing and selections use the Playwright build used by Playwriter, including its target checks. Desktop supplies the runtime; no separate Node installation is needed. Site rules, protected fields, Stop and your approval choices continue to apply. By @crmne.

## Known limitations

- **Full cross-platform validation was still running when this release was started.** Local runtime, native UI and browser regression checks passed. The remaining [CI results](https://github.com/crmne/chatwithwork-desktop/actions/runs/41076339414) are tracked separately.

- **Linux animations can still remain at 60 fps.** A Chromium-based prototype reached 120 fps, but that runtime migration is not part of this release.
- **The reported brief flash on every computer-settings tab has not been conclusively reproduced.** Startup white frames were reproduced and fixed; tab navigation preserves the native document in testing.
- **Automatic recovery of the website's computer-settings panel needs a current Chat with Work server.** Update self-hosted servers too.
- **The browser extension is still installed manually.** Replace its files and press Reload on its extension card. Older extension/runtime combinations keep the previous browser implementation; Linux Arm64 musl also keeps that implementation.
- **Linux updates use the package manager or one-line installer.** On Mac, use the signed and notarized DMG; the PKG remains unsigned. Windows SmartScreen may warn while the installer builds reputation.
